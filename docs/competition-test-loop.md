# 경쟁대회 테스트 운영 절차

테스트는 질문별로 중단 가능한 단위로 실행합니다. 실행기는 HTTP 요청, 응답 원문, 기본 문구 판정, 꼬리 질문, 회차별 Markdown·JSONL 저장을 담당합니다. 기대 답변의 의미 비교와 근본 원인 분석은 결과를 확인한 뒤 진행합니다.

## 기본 실행

```powershell
python scripts/run_competition_tests.py `
  --base-url http://49.50.142.35:8000 `
  --cases test_cases/competition-round-template.json `
  --output-dir "C:\Users\idong\OneDrive\바탕 화면\공모전\2026 미래에셋 ai 페스티벌\테스트\2026-09-05_03차"
```

기본값은 첫 실패에서 멈춥니다. 실패한 case의 `원인분석.md`에 직접 원인, 유사 유형 점검, 꼬리 질문 결과, 근본 원인, 로컬 테스트, 커밋을 기록한 뒤 코드를 수정하고 다음 case를 별도로 실행합니다.

특정 case만 실행하려면 `--case-id R-03`을 추가합니다. 전체 목록을 끝까지 실행해 현황을 수집하려면 `--continue-on-failure`를 추가합니다. 기존 회차를 다시 쓸 때만 `--overwrite`를 사용합니다.

## 생성 파일

- `배포상태.json`: 실행 당시 `/health`, `/ready`, 서버 주소와 시각
- `<case-id>/응답.json`: 원본 응답과 HTTP·판정 정보
- `<case-id>/결과.md`: 질문, 기대 기준, 실제 답변, 자동 판정
- `<case-id>/원인분석.md`: 실패 시 분석 템플릿
- `<case-id>/꼬리질문-*-응답.json`: 실패 시 실행한 꼬리 질문 응답
- `전체결과.jsonl`: 실행한 case별 구조화 결과
- `진행기록.md`: 회차 요약과 다음 작업

## 수정과 배포 순서

실패하면 먼저 유사한 지표·기간·기업·집계 범주에 같은 문제가 있는지 꼬리 질문으로 확인합니다. 그 결과를 바탕으로 공통 원인을 수정하고, 관련 로컬 회귀 테스트와 전체 `pytest`를 실행합니다. 수정사항별로 파일을 묶어 커밋한 뒤 다음 질문으로 넘어갑니다. 모든 질문의 탐색이 끝나면 커밋을 한 번에 push하고 서버에서 pull·build·recreate·deployment check·`/ready`를 실행합니다. 마지막으로 전체 케이스를 다시 실행해 최종 재검증 결과를 각 문서에 추가합니다.
