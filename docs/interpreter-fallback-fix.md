# Interpreter HyperCLOVA fallback 수정 및 검증

2026-09-06 로컬 검증 기록.

## 원인

- 로컬 `.env`에는 `INTERPRETER_USE_LLM`이 없었고 예제는 `0`이었다.
  Compose는 답변용 `CLOVA_LLM_ENABLED`만 켰으므로 슬롯 보완은 활성화되지 않았다.
- 호출 조건은 기업·지표·의도 누락만 검사해 기간, 기업 모호성, 계산 연산·분모 누락을 놓쳤다.
- 기업을 보완해도 기존 ambiguous 표시가 남았고, 지표를 채워도 공시 검색 설정과
  기존 계산계획이 갱신되지 않았다.
- 슬롯 JSON도 semantic validation의 짧은 출력 한도를 공유했다.
  이는 응답 잘림 위험이며 이번 실측에서 잘림 자체를 재현한 것은 아니다.
- 호출 예외가 기록 없이 무시되어 미호출과 실패를 구분하기 어려웠다.

## 변경

Compose 기본값 및 예제, 로컬 환경에서 슬롯 보완 활성화. 명시적 `0`은 지원한다.
누락 조건 확대, 허용값·타입 검증, 보완값의 필터·계산 반영, 해소된 기업 모호성 제거,
별도 출력 한도(1024), 실패 종류 기록을 적용했다. 재질문 정책 자체는 변경하지 않았다.
허용 enum을 확장하지 않으며, 문맥으로 특정할 수 없는 값은 추측하지 않도록 프롬프트에 명시한다.

## 검증

- 규칙 기반 gold-query: 40/40 및 불변식 검사 통과.
- 실제 HyperCLOVA를 주입한 gold-query: 40/40 기대값 일치.
- 실제 호출: `삼성전자 이천이십오년 매출액은?` → `llm_used=True`,
  `route=ok`, 검색 연도 `[2025]`.
- 전체 기본 로컬 테스트 및 corpus 전용 테스트 통과.
- 네트워크 없는 회귀 테스트로 누락 슬롯, 기업 모호성, 계산계획 갱신,
  실패·비정상 응답, 호출 생략, 독립 토큰 한도를 확인한다.

서버 배포·컨테이너 재생성은 실행하지 않았다. 실제 호출 검증은 Interpreter 단계이며,
검색부터 최종 답변까지의 서버 정확도 검증을 의미하지 않는다.
